# my3dprinter.io — instructions

Static Next.js site (output: export). `npm run build` → `out/` → `dist/` (scripts/postbuild.mjs adds llms.txt). Then `python3 scripts/check-seo.py` must report 0 issues. Push to `main` → GitHub Actions builds and publishes the `site` branch → the promt-site server pulls it every 5 minutes (deploy/add-site.sh). Site language: **English**. Company name in legal text: OUTRANKING LTD only (no company number, no address).

## What the site is
1. **Tools** (lib/data/tools.ts): converters, viewers, image→3D, SVG→3D, DDS textures. Everything runs in the browser (three.js, occt-import-js for STEP/IGES, fflate). Never add server uploads or paid APIs.
2. **Printers** (`content/printers/*.md`): one page per printer model or brand hub.
3. **Blog** (`content/blog/*.md`, URL `/blog/<slug>/`): comparisons (X vs Y), setup/connection/firmware, how-to, troubleshooting, filament, ideas, buying guides.
4. Format pages (lib/data/formats.ts) and static pages (`content/pages/`).

## Adding a converter
Add an entry to `TOOLS` in lib/data/tools.ts only if the engine really supports both formats (inputs: lib/engine/load.ts; outputs: lib/engine/export.ts). Add pair-specific `NOTES` for high-volume pairs. Test the conversion in a real browser (Playwright + /usr/bin/google-chrome) before publishing. Do not create pages for conversions we cannot do (FBX/STEP/BLEND/SLDPRT output, BLEND/SLDPRT/SKP input).

## Content plan (all pages come from docs/3d-printing-keywords.xlsx)
- `blog-keywords.md` — blog articles, sorted by KD (easiest first), then volume. One line = one article; its variants go into H2s and the FAQ.
- `pages-plan.md` — printer model pages, brand hubs, converters, viewers, format pages.
- Both are generated by `python3 scripts/build-plans.py` from the Excel file and docs/questions.tsv. Do not re-run it after you start ticking lines (it would reset ticks); edit the .md files directly.
Put the main keyword in `seoTitle`, the H1 (`title`), the first sentence and one FAQ question. After publishing, tick the line and add the path (`blog/slug` or `printers/slug`).

## Front matter
```yaml
---
title: H1 of the page (contains the keyword)
seoTitle: ≤ 60 chars, contains the keyword
description: 70–160 chars, unique
date: YYYY-MM-DD
updated: YYYY-MM-DD   # when revised
category: e.g. Bambu Lab | Creality | Prusa | Comparisons | Setup and software | Troubleshooting | Filament and materials | Files and slicers
summary: [3 one-sentence facts]
faq: [3–4 items, q/a]
sources: [{name, url}]   # required on printer pages and comparisons; NOT shown on the page (verification record + structured data only)
specs: [["Label", "Value"], ...]   # printer pages only, from the maker's official spec page
tools: [tool slugs to show in the sidebar]
---
```
File name: `content/<printers|blog>/YYYY-MM-DD-slug.md` (date = today in Asia/Tashkent). Slug = URL.

## Page structure
- First sentence answers the query in bold with the keyword.
- Printer page: who it suits → setup (high level, from the official quick start) → connecting (Wi-Fi/app/LAN/SD) → manual (say where the official manual is, e.g. "on the Bambu Lab Wiki", as plain text without a link; never copy it) → firmware/software → compare links.
- Comparison: at-a-glance table → what the differences mean → which to buy.
- Troubleshooting: symptom → causes → fixes in order → prevention.
- 2–5 internal links to tools and other pages. Use only paths that exist.
- **No external links anywhere on the site (owner's rule):** no links to other websites in the text, FAQ, summary or templates — not to manufacturers, wikis, model libraries or competitors. Mention a source by name in plain text if needed; URLs go only into `sources` in the front matter.

## Images (owner's rule: every blog and printer page has one)
- Generate one unique 16:9 illustration per new page with the Animx connector: `generate_image`, model "GPT Image", aspectRatio "16:9". At most 8 render at once; queue the rest.
- Style: clean modern editorial digital illustration, soft light, deep navy and warm orange accents, "no text, no logos, no brand names". Printers: always a **generic, unbranded** printer of the same type ("not a photo of any real product") — never imitate a real product photo or logo. No real people.
- Each prompt must show a different scene from all existing ones (check `imageAlt` values in content/).
- Front matter: `image: https://assets.animx.ai/gen/<user>/<generationId>/output.png` (the URL from get_generation, or the same pattern) and `imageAlt: Illustration of …`. `scripts/fetch-images.mjs` downloads it to public/images/<dir>/<slug>.webp during the CI build; pages without a downloaded image show a styled placeholder.

## Accuracy rules (strict)
- Specs, prices, dates and feature claims only from the manufacturer (spec page, wiki, manual, blog) or, if missing there, two reputable sources that agree. List them in `sources`. If sources disagree or a number is missing, leave it out.
- Launch prices must be labelled as launch prices with the region. Do not state current prices.
- No invented test results, quotes, user numbers or reviews. We do not claim to have tested printers.
- Never copy manuals or competitor text; write in your own words. Name the official manual as plain text (no link).
- Brand names are trademarks; we are independent. No logos or official product photos.
